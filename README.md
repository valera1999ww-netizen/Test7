# Telegram Referral Roulette Bot

Готовий Telegram-бот на Python 3.11 + aiogram 3.31.0 із:

- реферальною системою;
- безкоштовними спінами;
- серверною рулеткою через Telegram Web App;
- SQLite локально та PostgreSQL через `DATABASE_URL`;
- балансом і історією транзакцій;
- заявками на виплату;
- перевіркою підписки на канал через Telegram Bot API;
- повною адмін-панеллю;
- розсилкою з обробкою заблокованих ботів;
- Render-конфігом.

## 1. Локальний запуск

Потрібен Python 3.11.

Створіть віртуальне середовище:

```bash
python3.11 -m venv .venv
```

Linux/macOS:

```bash
source .venv/bin/activate
```

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Встановіть залежності:

```bash
pip install -r requirements.txt
```

Скопіюйте `.env.example` у `.env` і заповніть значення:

```env
BOT_TOKEN=123456:YOUR_TOKEN
ADMIN_IDS=123456789
CHANNEL_ID=@your_channel
CHANNEL_URL=https://t.me/your_channel
DATABASE_URL=
WEBAPP_URL=https://your-public-https-host/webapp
```

Після цього:

```bash
python bot.py
```

При запуску без `DATABASE_URL` бот створює локальний файл `bot.db`.

## 2. Telegram-канал

Бот повинен мати доступ до каналу, який вказаний у `CHANNEL_ID`. Для надійної перевірки членства через `getChatMember` рекомендується додати бота адміністратором каналу.

`CHANNEL_ID` може бути:

```text
@username_каналу
```

або числовим ID:

```text
-1001234567890
```

`CHANNEL_URL` — звичайне посилання на канал, яке відкриває кнопка «Підписатися на канал».

## 3. Telegram Web App

Рулетка не визначає виграш у JavaScript. Клієнт отримує тільки результат від `/api/spin` і використовується для анімації.

Сервер:

1. перевіряє Telegram `initData` через HMAC-SHA-256;
2. дістає реальний Telegram ID;
3. атомарно списує один спін;
4. перевіряє конфігурацію шансів;
5. визначає виграш на сервері;
6. додає виграш до балансу;
7. створює запис у `spins` і `transactions`.

`initData` перевіряється за алгоритмом Telegram Mini Apps; застарілі дані відхиляються.

`WEBAPP_URL` має бути HTTPS, наприклад:

```text
https://referral-roulette-bot.onrender.com/webapp
```

Саме цей URL вставляється в кнопку Web App у боті.

## 4. Реферальна система

Посилання має формат:

```text
https://t.me/BOT_USERNAME?start=USER_ID
```

Реферал зберігається при першому заході за deep-link і зараховується лише після успішної перевірки підписки.

Для одного `referred_id` існує `UNIQUE`, тому повторні `/start` не створюють нових рефералів.

За кожні 5 підтверджених рефералів система нараховує +1 спін. Система зберігає кількість уже виданих referral-spins, тому одна п'ятірка не може бути нагороджена вдруге.

## 5. Початкові шанси

При першому запуску в `roulette_prizes` автоматично створюються:

```text
10 грн   — 55%
20 грн   — 30%
30 грн   — 5%
50 грн   — 0%
100 грн  — 0%
200 грн  — 0%
300 грн  — 0%
500 грн  — 0%
1000 грн — 0%
```

Адмін змінює шанс окремого призу з адмін-панелі. Після зміни сума активних шансів повинна бути рівно 100%.

## 6. Виплати

Мінімальна сума виплати встановлена в коді:

```text
50.00 грн
```

При створенні заявки сума одразу знімається з доступного балансу та резервується. Це не дає користувачу витратити ті самі кошти вдруге.

Статуси:

- `pending` — очікує виплати;
- `paid` — виплачено;
- `rejected` — відхилено.

При відхиленні сума повертається на баланс.

## 7. Адмін-панель

Адміни беруться з `ADMIN_IDS`:

```env
ADMIN_IDS=123456789,987654321
```

Адмін-панель має:

- користувачів;
- керування балансом;
- налаштування рулетки;
- видачу/зняття спінів;
- виплати;
- розсилку;
- статистику;
- історію виграшів;
- налаштування;
- список заблокованих користувачів.

Всі ручні зміни балансу і важливі адмінські дії пишуться в `admin_logs`.

## 8. База даних

Таблиці:

## 9. Render

Render може запускати Python web service з довільним ASGI/HTTP сервером; процес має слухати `0.0.0.0` на порті Render. Цей проєкт запускає FastAPI та aiogram polling в одному web service. `render.yaml` уже містить build/start/health-check налаштування.

### Варіант через GitHub

1. Створіть новий GitHub repository.
2. Завантажте всі файли цього проєкту в корінь repository.
3. Відкрийте Render.
4. Оберіть **New → Blueprint** або **New → Web Service**.
5. Під'єднайте GitHub repository.
6. Якщо використовуєте Blueprint, Render прочитає `render.yaml`.
7. Додайте Environment Variables.
8. Зробіть Deploy.
9. Перевірте `https://YOUR-SERVICE.onrender.com/health`.
10. Після першого деплою скопіюйте URL сервісу та встановіть:

```env
WEBAPP_URL=https://YOUR-SERVICE.onrender.com/webapp
```

11. Зробіть redeploy.

### Environment Variables на Render

Обов'язково:

```text
BOT_TOKEN
ADMIN_IDS
CHANNEL_ID
CHANNEL_URL
DATABASE_URL
WEBAPP_URL
```

Для production рекомендується PostgreSQL через `DATABASE_URL`. Не залишайте production-дані лише в SQLite на Render без окремого persistent storage: звичайна файлова БД залежить від файлової системи сервісу.

## 10. Що має бути в Telegram BotFather

Для звичайної роботи достатньо токена бота.

Для Web App URL повинен бути HTTPS.

Кнопка «🎡 Крутити колесо» відкриває Web App через `WebAppInfo`.

## 11. Безпека

У коді:

- токен не зберігається в Git;
- адміни визначаються через ENV;
- Web App `initData` перевіряється на сервері;
- клієнт не може передати суму виграшу;
- один spin списується атомарним SQL `UPDATE ... WHERE spins > 0`;
- виграш генерується на сервері;
- виплати перевіряються на сервері;
- гроші при створенні заявки резервуються списанням із доступного балансу;
- відхилена виплата повертається на баланс;
- важливі фінансові зміни логуються.

## 13. Швидкий тест функціоналу

1. Новий користувач запускає `/start`.
2. Отримує екран підписки.
3. Натискає підписку та `✅ Я підписався`.
4. Отримує рівно один welcome-spin.
5. Повторний `/start` не дає другий welcome-spin.
6. Через `/start=USER_ID` перевіряється реферальний зв'язок.
7. Після 5 підтверджених рефералів реферер отримує +1 spin.
8. Рулетка відкривається в Web App.
9. Результат приходить тільки із сервера.
10. Spin списується один раз.
11. Виграш додається до балансу.
12. Вивід списує доступний баланс і створює `pending`.
13. Адмін може підтвердити або відхилити виплату.
14. При відхиленні кошти повертаються.
15. Розсилка позначає користувачів, які заблокували бота, як inactive.
